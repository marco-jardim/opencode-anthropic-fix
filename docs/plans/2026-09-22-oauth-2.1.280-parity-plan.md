# OAuth 2.1.280 Parity — Implementation Plan

> **For agentic workers:** execute this plan wave by wave, start to finish,
> without pausing for confirmation. Stop only for (a) a genuine ambiguity that
> needs a human decision, or (b) a critical/blocking defect that invalidates the
> approach. Everything else — including QA findings — is remediated inside the
> wave that produced it.

**Goal:** bring this plugin's OAuth implementation to byte-level parity with the
genuine Claude Code `2.1.280` client, remove every request the genuine client
does not make, and add the two authentication surfaces it has that this plugin
lacks (conditional scopes, OIDC federation) — without regressing any existing
account, token, or wire behaviour.

**Evidence base:** `D:\git\claude-code-wire-compat\docs\protocol\versions\claude-code-2.1.280-analysis.md`,
section 13.8. Every constant in this plan is transcribed from that document,
which in turn records byte offsets into the carved `2.1.280` win32-x64 bundle.
**No value in this plan may be guessed, interpolated from an older release, or
copied from another platform's build.** If an implementer finds a value this
plan does not specify, that is an ambiguity — stop and ask.

**Architecture:** pure ESM `.mjs` + JSDoc. `lib/` modules are leaves and never
import `index.mjs`. OAuth grows from one 537-line module into a small module
family with one clear owner per concern, so that waves can run in parallel
without two agents ever holding the same file.

**Tech stack:** Node ≥ 20, vitest 4.0.18, ESLint 10 flat config, Prettier 3.8,
husky + lint-staged. No new production dependencies. No TypeScript.

**Exit criteria (global):** see §"Global Definition of Done".

## Orchestration rules (concurrency safety)

These are hard constraints on the orchestrator, not suggestions.

1. **Single-writer invariant.** At any instant, each file has at most one agent
   authorised to write it. The "Owner" column in each phase's file table is that
   authorisation. An agent that needs to write a file it does not own must stop
   and report, never write.
2. **No read-during-write.** An agent may not read a file that another agent is
   currently authorised to write. If a phase needs file `A` as context while
   another phase is editing `A`, the two phases are sequential, not parallel.
3. **Parallelism is declared, not inferred.** Each wave states which phases may
   run concurrently. Phases not listed as concurrent are strictly sequential.
4. **Fan-out reads are free and encouraged.** Multiple `@fast` agents reading
   _different_ files in the same message is the default for every pre-flight.
5. **Commit often.** One commit per task, Conventional Commits, `git commit -s`,
   staged by explicit path — never `git add -A`. A commit that requires a
   companion test change to stay green lands both in the same commit, with the
   reason in the body.
6. **The tree is never left red.** If a wave cannot finish green, revert to the
   last green commit and escalate.
7. **Always full paths.** Every file reference in a dispatch is absolute,
   beginning `d:\git\opencode-anthropic-fix\`.

# Wave 1 — Endpoint and fingerprint parity

**Why this wave exists:** drift rows 1–5 are the ones that make this plugin
identifiable on the wire _today_. A wrong authorize host, a stale SDK version, an
extra body key, and an entire HTTP request the genuine client never makes are
four independent fingerprints. This wave closes all four and removes the dead
axios path that can only ever make a user more identifiable. It is the wave that,
on its own, delivers the plan's headline value.

### Decision recorded: the axios fingerprint path is retired

`oauth.sdk_token_useragent: false` currently selects `axios/1.13.6` headers. The
genuine 2.1.280 client has no axios path at all. A user who sets this flag to
`false` does not become _more_ anonymous; they become the only client on the
network sending that shape. Keeping a switch whose only effect is to degrade the
product's core promise is not a feature.

**Resolution:** remove the axios code path. Retain the config key as a
_recognised-but-inert_ key that emits a one-time deprecation warning, so existing
`opencode.json` files keep loading. Document the removal in the contract doc's
"Divergences" section. This is a behaviour change to a public config key and is
therefore called out here rather than buried in a task.
